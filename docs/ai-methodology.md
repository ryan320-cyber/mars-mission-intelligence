# AI Methodology & Grounding Architecture

Architecture and anti-hallucination guardrails for the **Mars Grounded AI Scientist**.

## 1. Dual-Mode Architecture

The AI Science Assistant operates in one of two modes, determined by runtime environment configuration:

### Mode A: Gemini LLM Grounded Model (when `GEMINI_API_KEY` or `GOOGLE_API_KEY` is set)
- Invokes Google Gemini 2.0 Flash via the `generativelanguage.googleapis.com` API.
- Every query is bound to structured telemetry context injected as a system prompt.
- The model is instructed to answer **exclusively** using the provided NASA telemetry context.
- Response is parsed as structured JSON matching the AI Answer Contract schema.
- `model_provider_status` = `GEMINI_2.0_FLASH_GROUNDED_MODEL`

### Mode B: Deterministic Rule-Based Scientific Assistant (default, no API key configured)
- Uses keyword-matching to classify the user's question into pre-defined scientific categories.
- Responses are hand-authored by domain specialists, grounded in verified telemetry statistics.
- Provides the same structured answer contract as the LLM mode.
- `model_provider_status` = `RULE_BASED_DETERMINISTIC_ASSISTANT`

> **Rule 3 Compliance:** The system never claims general-purpose LLM reasoning when operating in
> deterministic mode. The frontend renders a visible badge indicating the active provider status.

---

## 2. Context Generation & Structured Telemetry Injection
Every query is bound to structured telemetry context extracted dynamically from the backend analytical pipeline:
- Active mission and landing coordinates (Gale Crater, Elysium Planitia)
- Calibrated summary statistics (mean, median, IQR, 5th/95th percentiles)
- Top 5 multivariate anomalies identified by Isolation Forest
- Current Martian Environmental Challenge Index (MECI) and factor breakdown
- PDS dataset collection URNs and DOIs

---

## 3. AI Answer Contract

Every response generated by the Mars AI Scientist strictly adheres to the structured Answer Contract:

| Field | Type | Description |
|---|---|---|
| `finding` | string | Direct empirical answer to the user's query |
| `data_evidence` | string | Actual numerical values, Sols, p-values, and statistics from loaded telemetry |
| `analytical_interpretation` | string | Planetary boundary layer physics and statistical inferences |
| `uncertainty` | string | Quantified sensor uncertainty, measurement precision, and confidence bounds |
| `limitations` | string | Missing sensor periods, spatial field-of-view limits, or model assumptions |
| `methods` | string | Analytical methods used (e.g., Mann-Whitney U, Isolation Forest, chronological ML) |
| `source` | string | Authoritative NASA PDS dataset identifier, mission name, and instrument |
| `sources` | string | All contributing data sources |
| `data_status` | string | `VERIFIED_NASA_OBSERVATIONS`, `DERIVED_ANALYTICS`, `SIMULATED_DEMO_BASELINE`, or `INSUFFICIENT_DATA` |
| `data_sufficiency` | enum | `HIGH`, `MODERATE`, `LOW`, or `INSUFFICIENT` |
| `evidence_links` | array | Clickable trace links to underlying data modules in the UI |
| `computed_at` | ISO 8601 | UTC timestamp when the response was computed |
| `model_provider_status` | string | Active AI provider mode (see Section 1) |

## 4. Anti-Hallucination Guardrails & Refusal of False Certainty

The system strictly enforces refusal criteria:

1. **Unmeasured Variables**: If a query asks for variables not present in verified meteorological telemetry (e.g., subsurface oceans, methane plumes, human life-support metrics, biosignatures, terraforming), the engine responds:
   > *"The requested subject is outside the scope of verified meteorological telemetry. No calibrated sensor telemetry exists in MSL REMS, InSight TWINS, or MRO MCS data products."*
   
   `data_sufficiency` = `INSUFFICIENT`, `data_status` = `INSUFFICIENT_DATA`

2. **Data Sufficiency Meter**: Every response outputs a verified data sufficiency rating:
   - `HIGH`: Over 100 continuous observations and validated uncertainty parameters.
   - `MODERATE`: Minor sensor gaps present; relative trends valid.
   - `LOW`: High missingness or localized uncalibrated interval.
   - `INSUFFICIENT`: Variable or temporal range absent.

3. **LLM Grounding Constraint**: When Gemini is active, the system prompt explicitly instructs the model to never fabricate measurements, citations, observation Sols, or physical phenomena. Response temperature is set to 0.1 and output format is constrained to `application/json`.

---

## 5. Signature Wow Moment #2: Data → AI Traceability

The AI response generates clickable evidence trace links (e.g., `[View Anomaly Timeline (Sol 2082)]`, `[Inspect MECI Factor Decomposition]`, `[Open Model Lab]`).

When clicked, these links immediately navigate the user interface directly to the underlying raw chart and telemetry points, creating inspectable accountability between AI claims and NASA empirical data.

---

## 6. Frontend Provider Status Badge

The `MarsAIScientist.tsx` component renders a visible badge in the module header indicating:
- **Gemini LLM Active** (emerald badge): When the backend has a configured and functioning Gemini API key.
- **Deterministic Assistant** (amber badge): When operating in rule-based fallback mode.

This ensures Rule 3 compliance: users always know whether they are interacting with an LLM or a deterministic engine.
